# 작업 프롬프트 사용법

현재 작업에 맞는 프롬프트 하나부터 선택한다. 공통 규칙은 [AGENTS.md](../AGENTS.md), 실행 계약은 [PROMPT_CONTRACT](../docs/agent/PROMPT_CONTRACT.md), 분야 지식은 `docs/`, 반복 작업 진입점은 `.agents/skills/`에 있다. 링크를 읽지 않는 AI 도구에는 참조 파일을 직접 제공한다.

## 디자인 작업 순서

새 UI는 **54 요구 질문 → 55 방향 비교·선택 → 56 화면 구현 → 57 실제 화면 검수** 순서로 진행한다. AI는 먼저 기존 자료를 확인하고 사용자에게 필요한 질문을 한 뒤 응답을 기다린다. 사용자가 이미 완성된 디자인과 구현 범위를 승인했다면 그 승인을 재사용한다. 17~20은 화면·사용 흐름·반응형·접근성의 분야별 검토이고 57은 실행 화면과 전후 증거를 중심으로 한다.

상태관리 결정은 58, 모션 설계는 59, 셰이더는 60, 공통 컴포넌트 예제는 61을 연결한다. 모든 과정을 매번 수행하지 말고 실제로 미정인 결정과 변경 범위에 맞춰 선택한다.

## 입력과 언어

작업 목표, 대상 파일/화면, 사용자 흐름, 플랫폼, 기존 결정, 수락 기준, 허용 범위를 전달한다. 새 디자인에는 참고 화면과 좋아하는 이유를 추가하면 좋다. 이미지 접근이 안 되면 AI가 확인하지 못한 부분을 분명히 표시해야 한다.

이번에 개정한 실행 본문은 영어로 작성했다. 사용자 질문·설명·최종 답변은 한국어이며, 제품 문구는 제품의 지원 언어를 따른다. 영어가 모든 모델에서 더 우수하다는 주장은 하지 않는다. 아직 개정하지 않은 다른 분야의 한국어 프롬프트는 유지했고 아래 표에 언어를 표시했다.

예시: “PROJECT.md를 읽고 54-design-brief를 적용해 줘. 새 기록 앱의 디자인을 정하려고 하니 필요한 내용을 먼저 질문해 줘.”

## 검증과 유지보수

공통 정책은 원본에서 고치고 도구별 어댑터는 링크만 유지한다. 실제 요청·산출물·실행 증거로 효과를 확인하며 파일 수나 설명 길이만으로 지침의 품질을 판단하지 않는다. 참조 출처와 적용하지 않은 규칙은 [조사 기록](../docs/REFERENCE_RESEARCH.md)에 있다.
