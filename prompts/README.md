# 작업 프롬프트 사용법

공통 지침은 `AGENTS.md`, 분야 정책은 `docs/`, 반복 수행 절차는 `.agents/skills/`에 있다. 이 목록은 한 번에 전부 읽는 자료가 아니라 현재 작업에 맞춰 선택하는 입력이다.

## 입력 방법

작업 목표·이슈 번호·수락 기준·대상 플랫폼·관련 파일·허용된 외부 작업을 먼저 전달하고 해당 프롬프트를 붙인다. 관련 파일은 경로로 연결하며 비밀과 개인정보는 입력하지 않는다. 각 프롬프트의 제목과 입력 안내 아래를 그대로 사용해도 된다.

예시 요청: “이슈 #142의 테마 선택을 구현해 줘. 설정은 이번 세션에서만 유지하고, 320px 폭·한국어·큰 글자에서 검증해 줘. 로컬 구현과 테스트까지 진행해 줘. 07-implement-feature 프롬프트를 적용해 줘.” 이 번호는 사용 예시이며 실제 이슈가 있다고 가정하지 않는다.

## 설계 근거

명확한 목표·파일 근거·제약·성공 조건·출력 형식으로 요청을 구조화한다. 장기 작업은 실행 계획·Git·테스트에서 복원한다. 외부 콘텐츠는 지시가 아닌 자료로 취급한다. 특정 모델의 역할 연기나 숨은 사고 과정 요청에 의존하지 않는다. 공식 지침과 확인 날짜는 [출처](../docs/SOURCES.md)를 참고한다.

## 검증과 개선

프롬프트가 실패한 실제 입력·생성 diff·실행 결과에서 원인을 찾는다. 필요한 정보와 검증 조건을 보완하고 새로운 작업에 적용해 반복 가능성을 확인한다. 모델별 어댑터에는 정책을 복제하지 않는다. 변경은 관련 스킬·연결 링크와 함께 검사한다.
