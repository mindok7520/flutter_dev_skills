# 디자인 및 Flutter 개발 지침 개선

## 요청과 범위

기존 [초기화 이슈 #1](https://github.com/mindok7520/flutter_dev_skills/issues/1)의 자료에 대한 후속 사용자 요청이다. 새 UI 작업 전에 사용자에게 질문하고 방향을 합의하는 절차, UI/UX 기본 규칙, 공개 저장소에서 검증한 상태관리·설계·성능·최적화·셰이더·애니메이션 지식을 실행 지침에 반영한다. 실행 본문은 영어, 사용자 설명과 README는 한국어로 정리한다. 실제 Flutter 앱은 생성하지 않는다.

## 수락 기준

- [x] Superpowers, 디자인 프롬프트, Flutter 분야별 저장소의 실제 파일·출처·확인 날짜·적용 결정을 기록한다.
- [x] 새 디자인 작업의 질문·응답·방향 합의와 기존 승인 범위 재사용을 명확히 한다.
- [x] 정보 구조·문구·색·글꼴·간격·입력·오류·접근성·반응형·시각 검토 기준을 연결한다.
- [x] 상태관리·아키텍처·측정 기반 최적화·셰이더·애니메이션의 선택 조건과 검증을 강화한다.
- [x] 영어 실행 지침과 한국어 설명의 범위 및 사용 순서를 README에 명시한다.
- [x] 원본 요구 파일, 어댑터, 링크, UTF-8, 새 프로젝트 복사와 스킬 동작을 검증한다. 독립 적용의 확인 범위와 중단된 정리는 아래에 구분한다.

## 실행 순서

1. 기존 자료 검증을 기준선으로 확보한다.
2. 공식 문서와 공개 저장소를 조사하고 재현 가능한 출처를 남긴다.
3. 공통 실행 규칙과 디자인 절차를 작성한다.
4. 분야별 문서·프롬프트·스킬과 한국어 사용 안내를 갱신한다.
5. 설치·문서 검증 및 독립적인 스킬 적용으로 수락 기준을 확인한다.

## 현재 기록

- 작업 브랜치: `codex/1-design-workflows`, 시작 커밋 `f18310e`.
- 작업 전 자료 검증과 기존 14개 테스트 통과. 변경 후 자료 검증과 19개 테스트 통과.

- 자료 개정 이후 사용자가 커밋과 푸시를 요청했다. 현재 변경과 검증 기록을 같은 커밋에 포함하고 `origin/codex/1-design-workflows`에 게시한다.

## 검증 명령과 결과

환경은 Windows PowerShell, Python 3.13과 별도의 검증 가상환경이다. 검증 대상은 `codex/1-design-workflows`의 작업 트리이며 앱 실행 성능을 검증한 커밋은 없다.

| 명령·검증 | 실제 결과 | 범위와 한계 |
| --- | --- | --- |
| `python scripts/validate.py` | 통과 | 원본·추가 요구 파일, 현재 작업 목록, Markdown 링크, UTF-8, YAML·JSON, 스킬 진입점, 어댑터와 CI 정책 |
| `python -m unittest discover -s tests -v` | 19개 통과, 25.785초 | 기존 14개와 작업 목록 검증 5개. 누락·중복·경로 이탈·잘못된 참조 및 설치 충돌·기존 파일 보존·재실행·복사 후 링크 검사 |
| 공식 `quick_validate.py` | 29개 스킬 통과 | 스킬 이름·메타데이터 구조. 행동 품질을 증명하는 검사는 아님 |
| 별도 대상 3곳에 `build_plan`과 `apply_plan` 적용 | 각각 384개 자료 파일 복사 | 최소 매니페스트가 있는 임시 대상. 본 저장소와 분리했고 기존 매니페스트 보존은 설치 테스트로 확인 |
| `git diff --check` | 통과 | 공백·패치 오류. 새 문서 내용과 요구 충족 여부는 별도 읽기 검토 |

## 독립적인 스킬 적용에서 확인한 결과

`skill-creator`의 실제 요청 형태 검증 지침에 따라 새 에이전트에 스킬 경로와 요청만 전달했다. 기대 답·의심한 문제·이전 분석은 전달하지 않았다. 대상은 시스템 임시 폴더의 `flutter-ai-design-research/design-task`, `state-task`, `shader-task`이며 본 저장소에는 예제 앱을 넣지 않았다.

| 요청 | 실제 관찰 | 판단과 한계 |
| --- | --- | --- |
| 학습 앱을 세련되고 고급스럽게 구성 | 사용자·기록 내용·확인할 정보를 먼저 질문하고 설계나 앱 파일을 만들지 않음 | 질문 우선 경계를 확인 |
| 사용자·기능·청록색 목록 방향을 제공하고 간격·글꼴을 위임 | `learning-journal-brief.md`에 승인·위임·기본값·미정을 구분하고 첫 화면 상태·입력·검수 기준 작성. 같은 디자인 승인 질문을 반복하지 않음 | 핵심 문서 산출물 검토 완료. 실행 계획의 최종 이동은 아래 중단에 해당 |
| 검색·계정 전환·오프라인 초안의 상태관리 결정 | `0001-learning-journal-state-management.md`와 검증 계획 작성. 지역 상태·ChangeNotifier·Riverpod·Bloc 비용 비교, 요청 세대·계정 경계·원자적 저장·복구 검증을 포함. 앱 검증은 미실행으로 기록 | 요구와 산출물의 계약을 직접 대조. 패키지 성능 우위나 구현 성공을 주장하지 않음. 최종 실행 계획 정리는 중단됨 |
| 방향이 정해진 물결 배경의 셰이더 검토 | `wave-background.md`에 기본 그리기·이미지·셰이더 대안, Canvas/ImageFilter 차이, 지원 환경·수명·정지 대안·실측 계획 기록 | 문서와 완료 기록의 실제 링크 확인. 기기 성능·동작은 미검증으로 유지 |

세 에이전트의 마지막 턴은 사용량 제한 오류로 끝났다. 이를 전체 독립 실행 성공으로 집계하지 않는다. 작성된 산출물은 주 에이전트가 직접 읽었다. 디자인·상태관리 산출물의 계획 링크가 아직 없는 `completed/` 경로를 미리 가리키는 중단 시 문제도 확인했다. 공통 실행 계약에 **실제 활성 경로를 먼저 연결하고 완료 이동 후 참조를 함께 갱신**하도록 보완했다. 이 보완을 새 독립 에이전트로 다시 실행하지는 못했으며, 저장소 자체의 링크 검증과 읽기 검토를 수행했다.

## 완료 상태와 적용 한계

요청한 재사용 자료·프롬프트·사용 안내 개정은 완료했다. 검증은 문서 구조, 도입 도구, 제한된 스킬 적용 사례를 대상으로 하며 모든 AI 모델의 준수나 실제 앱의 디자인·성능을 보증하지 않는다. 화면 실행·기기 빌드·상태관리 코드 검증은 이 자료를 도입한 실제 앱에서 수행한다.

후속 사용자 요청에 따라 `codex/1-design-workflows`에서 커밋과 원격 푸시를 진행한다. 이 기록을 포함한 커밋은 `git log -- docs/exec-plans/completed/1-design-workflows.md`로 식별하며, 실제 게시 결과는 원격 브랜치와 최종 작업 보고로 확인한다. PR 생성은 이번 요청에 포함되지 않는다. 다음 사용 단계는 루트 README의 도입 절차에 따라 대상 앱을 준비하고, 02번으로 제품 정의를 작성한 뒤 54~57번으로 디자인 질문·방향·구현·검수를 진행하는 것이다.
