# 설계 결정 템플릿

이 문서는 작성 양식이다. 복사본의 각 항목에 실제 결정과 근거를 기록하고 빈 항목은 이유·담당자·결정 기한을 명시한다.

| 항목 | 기록 내용 |
| --- | --- |
| 번호·제목 | 결정의 안정적인 식별자와 핵심 변화 |
| 상태·날짜 | proposed / accepted / superseded / rejected와 결정일 |
| 관련 작업 | 이슈·PR·실행 계획·이전 ADR |
| 소유자·승인 | 실제 책임자와 승인 증거 |

## 문제와 조건

현재 동작, 해결할 문제, 사용자·플랫폼·데이터·보안 제약을 기술한다. 사실과 가정을 구분한다.

## 대안 비교

최소 두 대안과 현상 유지를 비교한다. 정확성·보안·복구·유지보수·검증·성능·비용·교체 가능성을 포함한다.

## 선택과 결과

선택한 방식·채택 이유·포기한 이점·새로운 위험을 적는다. 외부 문서는 확인 날짜·실제 사용 버전·공식 URL을 기록한다.

## 구현과 전환

영향 파일·데이터 마이그레이션·호환 기간·점진 적용·되돌림·관측을 적는다.

## 검증과 재검토

성공 기준·실제 명령·측정 조건·결과·잔여 위험을 남긴다. 결정을 다시 검토할 사건이나 날짜를 지정한다.
